# Бот предложки треков

Telegram-бот принимает предложки в личных сообщениях, пересылает их в чат модераторов и даёт модераторам обработать каждую предложку кнопками. Данные пользователей, текст предложек, решения и настройки хранятся в SQLite. Медиафайлы в SQLite не загружаются: для них сохраняются Telegram `file_id` и технические метаданные.

## Возможности

- Принимает личные сообщения и вложения: текст, фото, документы, аудио, видео, голосовые и видеосообщения, стикеры и другие типы, которые Telegram разрешает копировать.
- Собирает сообщения Telegram-альбома по `media_group_id` и пересылает альбом модераторам одной группой.
- Прикладывает к предложке имя отправителя как ссылку на профиль, Telegram ID, дату, текст сообщения и кнопки модерации.
- Отправляет на `/start` приветствие, настраиваемое суперпользователем.
- После каждой принятой предложки отвечает отдельным настраиваемым текстом-подтверждением.
- Позволяет принять или отклонить предложку, написать свой ответ из чата модераторов, заблокировать или разблокировать отправителя.
- После решения меняет кнопки на карточке на «Ответить по новой». В карточке отображается принятое решение либо отправленный модератором текст.
- Ведёт счётчики сообщений, принятых и отклонённых предложек по пользователям.
- Содержит постраничный список заблокированных пользователей в меню суперпользователя.

## Переменные окружения

Создайте `.env` рядом с `bot.py` или задайте эти переменные в окружении контейнера:

| Переменная | Обязательна | Назначение |
|---|---:|---|
| `BOT_TOKEN` | Да | Токен бота от [@BotFather](https://t.me/BotFather). |
| `OWNER_IDS` | Да для меню управления | Telegram ID суперпользователей. Несколько ID указываются через запятую, например `111111,222222`. |
| `MODERATION_CHAT_ID` | Да | ID группы/супергруппы модераторов, обычно отрицательное число вида `-100...`. Бот должен состоять в чате и иметь право отправлять сообщения. |
| `DATABASE_PATH` | Нет | Путь к SQLite. По умолчанию `/app/data/bot.db`. |
| `TIMEZONE` | Нет | Часовой пояс дат, по умолчанию `Europe/Moscow`. |

Пример `.env`:

```dotenv
BOT_TOKEN=123456:replace-this-token
OWNER_IDS=123456789,987654321
MODERATION_CHAT_ID=-1001234567890
DATABASE_PATH=/app/data/bot.db
TIMEZONE=Europe/Moscow
```

Не коммитьте `.env` и не публикуйте токен бота. Для репозитория используйте шаблон без секретов.

## Установка и запуск

Требуется Python 3.11+ и зависимости из `requirements.txt`:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python bot.py
```

В контейнерном окружении задайте перечисленные переменные и обеспечьте постоянное хранилище для `/app/data`. Важно: текущий `docker-compose.yml` монтирует именованный volume `bot_data` в `/app/data` и задаёт `DATABASE_PATH=/app/data/bot.db`. Он использует `build: .`, поэтому в контексте сборки должен присутствовать Dockerfile (в этой копии репозитория он не включён). Если образ собирается средствами хостинга, используйте их текущую конфигурацию сборки и сохраните постоянный том на `/app/data`.

После запуска в логе появляется имя бота, ID чата модерации, путь к базе и сообщение о начале polling. Если бот не может отправить карточку, проверьте `MODERATION_CHAT_ID`, членство бота в группе и права отправки.

## Сценарий пользователя

1. Пользователь открывает личный чат с ботом и отправляет `/start`.
2. Бот отвечает текстом приветствия из настройки **«Изменить приветствие /start»**. При первом запуске используется значение по умолчанию.
3. Каждое последующее сообщение от пользователя обрабатывается как отдельная предложка. Текст, подписи к медиа и метаданные сохраняются; вложения копируются в чат модераторов.
4. Для альбома бот короткое время собирает сообщения одной media group, затем сохраняет их как одну предложку и копирует группу модераторам.
5. После пересылки бот отвечает на сообщение пользователя текстом из настройки **«Изменить подтверждение»**.
6. Если пользователь заблокирован, его сообщения не пересылаются и бот ему не отвечает.

## Сценарий модерации

В чате модераторов бот публикует материалы предложки и отдельную карточку с автором, Telegram ID, временем, текстом и кнопками. Имя в карточке ведёт на профиль автора; если username отсутствует, используется ссылка вида `tg://user?id=...`.

### Кнопки новой предложки

- **Принять трек** — отправляет пользователю настроенный текст принятия.
- **Отклонить** — отправляет настроенный текст отказа.
- **Ответить самому** — бот публикует в чате модераторов подсказку. Модератор должен ответить текстом реплаем на эту подсказку. Ответ отправляется пользователю реплаем на его исходное сообщение.
- **Заблокировать пользователя** — включает блокировку пользователя. Кнопки на его карточках заменяются на **«Разблокировать пользователя»**.

После принятия/отклонения кнопки меняются на **«Ответить по новой»**, а в карточке появляется статус **«Было принято»** или **«Отклонено»**. После ручного сообщения отображается **«Отправлен свой текст»** и текст ответа. Нажатие **«Ответить по новой»** возвращает обычные кнопки модерации.

Блокировка применяется ко всему пользователю, а не только к одной предложке. Разблокировка через кнопку на карточке или список в меню снимает блокировку пользователя и возвращает кнопки на его карточках.

## Меню суперпользователя

Telegram ID суперпользователей задаются в `OWNER_IDS`. Пользователь с таким ID получает панель при отправке `/start` боту.

В меню доступны:

- **Изменить приветствие /start** — бот попросит отправить новый текст приветствия.
- **Изменить подтверждение** — текст после принятия предложки.
- **Изменить текст принятия** — ответ пользователю при одобрении.
- **Изменить текст отказа** — ответ пользователю при отклонении.
- **Заблокированные пользователи** — постраничный список (по 8 пользователей) с кнопкой разблокировки напротив каждого имени.

При настройке текста отправьте новое текстовое сообщение. `/cancel` отменяет ввод настройки.

Также доступна команда в личном чате с ботом:

```text
/unblock <telegram_id>
```

Например, `/unblock 123456789`. Команда доступна только ID из `OWNER_IDS`.

## Данные SQLite

По умолчанию используется `/app/data/bot.db`. Родительская папка создаётся при подключении; контейнеру нужны права записи. При использовании контейнера путь следует подключить к постоянному volume, иначе база может пропасть при пересоздании контейнера.

### Таблицы

- `users` — Telegram ID, имя, фамилия, username, даты первого и последнего обращения, общее количество входящих сообщений, количество принятых и отклонённых предложек, статус и данные блокировки.
- `submissions` — предложки, автор, текст, тип содержимого, время, статус, ID исходных сообщений, Telegram `file_id`/метаданные медиа и ID карточки модерации.
- `replies` — история решений и ответов модераторов: кто, когда, тип решения и текст.
- `settings` — настраиваемые тексты приветствия, подтверждения, принятия и отказа.

Счётчик `message_count` увеличивается на каждое сообщение Telegram; элементы альбома считаются отдельными сообщениями, хотя сам альбом записывается одной предложкой. Счётчики `accepted_count` и `rejected_count` увеличиваются при соответствующем решении. Инициализация автоматически добавляет эти колонки в существующую таблицу `users`, если их там ещё нет.

Сами бинарные данные изображений, аудио и видео в базу не помещаются. Сохраняются Telegram file ID, тип и некоторые атрибуты файла; для показа материалов в чате используется копирование исходного сообщения Telegram.

## Ограничения и замечания

- Бот должен иметь возможность писать пользователю: пользователь должен сначала открыть диалог с ботом и отправить ему сообщение. Если Telegram запрещает отправку (например, пользователь заблокировал бота), ответ не будет доставлен.
- Сбор альбома использует короткое окно ожидания; стандартное поведение Telegram обычно присылает элементы подряд. Невозможно гарантировать сбор элементов, которые Telegram не доставил боту.
- Для модераторских ручных ответов используйте именно Reply на сообщение-подсказку бота. Ответы на другие сообщения в чате не привязаны к предложке.
- Состояние ожидания ручного ответа хранится в памяти процесса; после перезапуска бота незавершённая подсказка перестанет принимать ответ. Уже сохранённые предложки и ответы остаются в SQLite.
- В текущем коде кнопки модерации не ограничены отдельным списком ID модераторов: доступ к ним имеет участник модераторского чата, способный нажать inline-кнопку. Суперпользовательские настройки, список блокировок и команда `/unblock` защищены `OWNER_IDS`.
- Если сообщение копируется в чат модераторов, но карточка или кнопки не появляются, проверьте логи контейнера и корректность ID чата.

## Разработка и проверка

Проверка синтаксиса:

```bash
python -m py_compile bot.py
```

Зависимости проекта перечислены в `requirements.txt`. Не храните `.env`, токен или рабочую базу `bot.db` в git.
